# 代码与测试边界

> 目的：防止“无限修复/加固”。不是所有债都要现在还，也不是所有异常都要兜底。
> 适用于 v0.6.x；改代码前先读这一页。

## 1. 功能边界

保留：

```
会話 / 解説 / 単語 / 例文
点词查询
回显翻译
本地 ASR + VOICEVOX/AivisSpeech
SRS + 错题本
设置 / 数据导出
```

不做：

```
× 五十音课程
× 完整字典
× 发音评分 / 跟读打分
× 场景课 / 多角色
× 手机端 / Web 端
× 新平台、新后端
```

功能冻结继续有效。新功能先讨论，不接受“顺手加一个”。

## 2. 代码边界

会动：

```
· 可复现的用户 bug
· 数据丢失 / 安全问题
· 明确影响主流程的回归
· 正在改的那块代码顺手收口
```

不会动：

```
× 为了“更整齐”重写渲染层
× 引入 TypeScript / 打包器
× 全仓 Prettier
× 把 155 个空 catch 全部治理
× 把 settings.js 继续拆到 200 行以内
× 把 llm.js 拆成 5 个文件
× 把 scan 做成完整 JS 解析器
```

重构只在两种情况下做：

```
1. 这次改动正好落在那个文件
2. 不拆就会让这次改动更容易出错
```

不为了“以后可能”提前拆。

## 3. 测试边界

现在覆盖的：

```
agent/ 纯逻辑：判分、SRS、黄卡、追问去重、例句校验、数据迁移、配置、ASR 契约
静态：settings 分区/脚本顺序；scan 的顶层声明、IPC 通道、注入、打包覆盖
端到端：npm run smoke（本地，真拉 Electron，6 步）
```

不覆盖：

```
× renderer 交互逻辑
× settings 的真实点击流程
× GUI 视觉回归
× LLM 输出质量
× ASR/TTS 真机音频质量
× Windows 真机
× mac + Windows 双平台 UI CI
```

测试原则：

```
· 不为 getter / 一行转发写测试
· 不为“理论上可能”的异常写测试
· 只测规则、契约、曾经真出过 bug 的路径
```

## 4. 修复 / 加固的准入

至少满足一个：

```
1. 有复现步骤
2. 有日志/数据证据
3. 是安全或数据丢失问题
4. 是当前正在改的代码的自然收口
```

不满足就只记录，不改。

加固的停止条件：

```
· 正常路径正确
· 有一个合理兜底
· 失败时用户能看到提示或日志
· test / scan / smoke 全绿
```

不要求：

```
× 每个 catch 都有日志
× 每个 IPC 都有超时
× 每个状态都有防御性拷贝
× 每个函数都有单元测试
```

## 5. scan / lint 的边界

scan 是项目自检，不是 ESLint：

```
支持：本项目实际使用的 classic JS 子集
不支持：完整 JS 语法、所有正则边界、所有 ASI 情况
```

修到“当前代码 + 常见写法”即可，不扩成 parser。

lint 如果加：

```
只查 agent/ + main/
只 warn，不阻塞
不上 Prettier
```

## 6. 什么时候算“做完了”

```
· npm test 全绿
· npm run scan 全绿
· npm run smoke 通过
· 没有已知阻塞用户的问题
· 已知债有记录
```

满足即停，不继续找“还能不能更好”。

## 7. 当前接受的债

```
· renderer 仍是经典脚本
· settings.js 已拆成 settings-*，当前较大的是 settings-assets.js
· llm.js 642 行
· 没有 lint/format
· 空 catch 较多
· IIFE 内部不参与跨文件重名检查
```

技术债不再单独维护清单；有证据的才修，其余记录在 NOTES / CHANGELOG。

## 8. 一句话

```
功能：冻结。
代码：只修有证据的问题，只拆正在改的地方。
测试：规则和契约优先，不为覆盖率而覆盖率。
加固：正常路径 + 一个兜底 + 可诊断，够了。
```
