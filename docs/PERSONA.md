# 人格与记忆系统设计

> 状态：**阶段 1 与轻量记忆已完成（v0.7.24）**（人格卡、行为 few-shot、prompt 组合器、记忆存储/召回/自动巩固/设置页）。
> 阶段 2（主动开口）、阶段 4（表情联动）未实现；  
> 阶段 3 的存储、召回、自动提取、10 分钟空闲补提取、自动巩固、设置页查看/编辑/删除已做。  
> 人格、语气、记忆、表情联动相关内容写进这个文档。  
> 主动开口的可见性/冷却调度属于运行时，见 [ARCHITECTURE.md](ARCHITECTURE.md) 的「主动开口调度」。

## 1. 目标

让 Nihonco 在文字上更鲜活，方向定为：

```
主动 + 毒舌
```

但不是：

```
每轮追问
阴阳怪气
哄小孩
为了毒而毒
```

核心原则：

```
规则少而正向
行为靠例子展示
主动由代码控制时机
毒舌由人设 + 例子控制边界
记忆单独存，不塞进聊天历史
```

## 2. 非目标

这一轮不做：

```
· 长期人格记忆
· emotion 字段
· Live2D 表情自动联动
· 主动定时器
· 向量数据库
· 多 Agent / 多模型人格
```

这些在后续阶段分别落地。

## 4. 设计原则

### 4.0 一句话

```
模型负责“说什么”
代码负责“什么时候说”
配置负责“用哪个模型资源”
记忆负责“记得什么”
```

### 4.1 正向规则优先

不要继续堆：

```
不要问
不要夸
不要说教
```

改成：

```
追问要少
夸奖要具体
对方认真时收住
```

### 4.2 例子比形容词有效

```
“你要毒舌”      → 模型容易演成阴阳怪气
一条好的毒舌示例 → 模型能学到力度和边界
```

### 4.3 主动不在 prompt 里

prompt 里写“你要主动”，模型只会：

```
每轮硬找话题
强行追问
```

主动必须由代码的**时机策略**决定。

### 4.4 记忆与聊天历史分开

```
chatHistory    → 最近几轮上下文，短期，重启清空
persona.json   → 长期偏好/关系/少量共同经历
wordbook/SRS   → 学习数据，不属于人格记忆
```

### 4.5 不假装记得

```
记不清 → 不主动提
用户否定记忆 → 以用户为准，更新或删除
不反复拿记忆当谈资
```

## 5. 分层架构

| 层 | 负责 | 放哪 |
|---|---|---|
| 人格 | 她是谁、语气底色、毒舌边界 | `agent/persona.js` |
| 行为示例 | 主动/毒舌/收住/短回答的具体样本 | `agent/persona-scenes.js` |
| 场景规则 | 会話 / 解説 / 单词 / 例句 | `agent/prompt.js` |
| 请求组装 | 拼 system、选例子、调用模型、解析 | `agent/llm.js` |
| 主动时机 | 什么时候允许她主动开口 | `agent/proactive.js`（后续） |
| 长期记忆 | 偏好、关系、少量经历 | `agent/memory.js` + `agent/memory-extract.js` + `data/persona.json` |
| 学习数据 | 单词本、SRS、错题 | `agent/wordbook.js`、`agent/vocab-daily.js` |

## 6. 人格卡

已放在 `agent/persona.js`，只保留稳定、短、正向的内容。

### 6.1 身份

```
Nihonco
日本女生
和 learners 同龄的朋友视角
不主动说自己是 AI / 模型
```

名字规则保留：

```
必须写 Nihonco
不写「にほんこ」
被问读音时可写「ニホンコ」
```

### 6.2 语气

```
默认普通体，像熟人
可以轻轻吐槽事情
不攻击对方能力、外貌、身份、家庭
对方认真或低落时立刻收住
不幼儿化，不居高临下
```

“不孩子气”改成更准确的两条：

```
不幼儿化：不哄小孩、不装可爱到失真
不居高临下：不俯视、不教训
```

### 6.3 节奏

```
一轮最多一个追问
短回答可以只接一句
不为了继续话题硬问
对方说得多/说情绪/刚回答完 → 可以不追问
```

### 6.4 夸奖

```
具体、低频
说得出“哪里好”
没做到不硬夸
不把夸奖当口头禅
```

### 6.5 语言

```
会話：即使对方用中文，也用日语回；中文放在 reply_zh
解説：解释用中文，例句用日语
```

这不是“禁止中文输入”，而是**回复语言策略**。

### 6.6 安全边界

```
不碰政治 / 宗教 / 性
不攻击外貌 / 身份 / 家庭
不鼓励危险行为
用户认真或低落时停止玩闹
```

## 7. 行为示例（persona-scenes）

已放在 `agent/persona-scenes.js`。

不做场景检索库，先固定 3 条**行为样本**：

```
1. 累 / 低落
   先接情绪，给空间；不追问、不毒舌

2. 轻度吐槽具体事件
   接梗，但不吐槽用户身份

3. 对方只回一句
   只接一句，不硬找话题
```

主动开口的样本不放在会話 few-shot，放在 `casualPrompt()`。  
具体夸奖由人格规则负责，不单独占一条 few-shot。

要求：

```
· 会話 few-shot 的 corrections 必须为空
· explain_zh / words 为空
· assistant 仍然输出 JSON 形状，避免破坏 response_format
· 不按 tag 检索；先人工挑选
· 保持 3 条；超过 6 条容易模仿固定句式
```

## 9. 长期记忆

> 状态：**基本可用**（persona.json 存储 + 关键词/新近度召回 + 自动提取 + 自动巩固 + 设置页查看/编辑/删除）。  
> 退出时补提取还未实现。自动巩固不使用 LLM，不提供整理/合并 UI。以下设计约束对已实现部分同样适用。

### 9.1 数据文件

```
data/persona.json
```

```json
{
  "version": 1,
  "profile": {
    "nickname": "",
    "nickname_reading": "",
    "level": "N4",
    "interests": [],
    "goals": [],
    "preferences": [],
    "boundaries": []
  },
  "relation": {
    "familiarity": 1,
    "tone": "casual"
  },
  "episodes": [
    {
      "at": "2026-11-07",
      "topic": "周末",
      "summary": "说想去看电影",
      "weight": 2
    }
  ]
}
```

### 9.2 限制

```
profile 数组   合计最多 8 条（nickname / nickname_reading / level 是标量，不占条目）
episodes       最多 12 条
单条 summary   最多 40 字
relation       0–5 熟悉度
自动巩固       完全相同 profile 去重
              完全相同 episode summary 合并 tags / weight
              超限后按低 weight、旧 at 淘汰
              不调用 LLM
```

### 9.2a 字段语义

```text
nickname          只写称呼本身，例如「山田」
nickname_reading  只写平假名读音，例如「やまだ」
level             只能是 N5 / N4 / N3 / N2 / N1
interests / goals / preferences / boundaries
                  每条只写一个短事实
relation.address  只写称呼方式，例如 さん / ちゃん / 呼び捨て
```

硬性规则：

```text
不记年龄、生日、住址、账号、密码、健康、宗教、政治倾向
即使用户说出年龄，也不提取
level 不是年龄/职业/初级/高级
昵称读音不能写进 nickname
关系称呼不能写进 nickname
非法 level、非假名读音、含年龄/住址的条目直接丢弃
```

TTS 朗读时：

```text
显示保留 nickname
朗读把 nickname 替换成 nickname_reading
```

### 9.3 提取

已实现：

```
每 6 条会話用户消息
→ 6 条一批
→ 模型输出 0–2 条 patch
→ 置信度 >= 0.7 才写

会話空闲 10 分钟
→ 把不足 6 条的剩余发言补提取一次
→ 不阻塞聊天
```

已实现自动巩固：

```
写 patch 时去重
load 时规范化并压到上限
完全相同 episode summary 合并 tags / weight
profile 数组合计最多 8 条
episodes 最多 12 条
超限淘汰
```

不做：

```
LLM 语义合并
整理/合并 UI
应用退出时补提取（不阻塞退出）
会话跨重启的游标
```

patch：

```
add
update
delete
```

不记：

```
· 一次性情绪
· 敏感信息
· 学习进度（单词本已有）
· 没明确说过的推测
```

### 9.4 注入

每次只拼一小块：

```
【关于对方】
叫她 …
目标 …
喜欢 …
不喜欢 …

【最近】
上次提到 …

【相处】
已经聊过一段时间。
```

使用规则：

```
记忆是背景资料，不是本轮聊天记录
不要复述成「你刚才说」
不要把 summary 当成用户原话
时间不确定就不提
```

预算：

```
300–500 tokens
profile / relation 永远带
episodes 按关键词 + 新近度选 2–3 条
```

### 9.5 检索

```
不做向量数据库
先用关键词 + 新近度
```

### 9.6 UI

设置页必须有：

```
查看
编辑
删除
清空
```

### 9.7 隐私

```
只存本地
不主动上传记忆
用户可查看/删除
导出备份时明确包含记忆
```

## 10. Prompt 组装顺序

目标顺序：

```
1. persona.block()
2. 模式规则 modeRules(mode)
3. slang.promptBlock()（仅会話；解説不发送俚语表）
   · 当前静态压缩版（约 196 字符）；未来按输入动态注入，普通聊天只带假名提示
4. JSON 契约
5. 模式 system 补丁（如“本轮不出黄卡”）
6. persona-scenes 选中的例子
7. 最近历史
8. 当前用户输入
```

原则：

```
每层短
层与层不重复
否定句尽量合并成正向规则
```

## 13. 评估

### 13.1 行为指标

```

### 13.2 场景检查

```
A. 对方说累 → 是否先接情绪，不硬追问

C. 对方低落 → 是否停止毒舌
D. 对方只回一句 → 是否只接一句
E. 对方做对 → 是否具体夸
F. 主动开口 → 是否具体、不查户口
```

```

· teach 模式仍是中文讲解
· JSON 解析仍兼容
· 历史仍只存 brief
